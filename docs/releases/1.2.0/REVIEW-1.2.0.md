# BetterCM 1.2.0：新一轮反馈的核实与取舍

2026-10-14。用户提供的 DeepSeek 文档作为审查线索；结论以现有传输队列、窗口生命周期和回归结果为准。

| 反馈 | 核实与处理 |
| --- | --- |
| 被取代的分组请求显示错误并改变高度 | 采纳取消与失败分开的处理。App 先核对菜单请求和 Superseded，再处理 Success；分组及搜索补全单独捕获 OperationCanceledException。真正的分组异常只有当前代次、当前请求、当前 GroupLoad 对象持有者才能显示。保留有效请求的错误提示。反馈中 ShowSettings、CancelPreview、Trigger 的时序推演不完全准确：这些路径本来会关闭旧菜单，重新 ShowAt 也递增代次；不能把所有取消都认定为可复现故障。 |
| expand 与 invoke 并发会直接杀掉读取宿主 | 未采纳“没有串行化”的判断。ShellConnection.SendAsync 本来就以 SemaphoreSlim 串行化整个请求和响应；InvokeAsync 在移交前设置 InvocationReserved，Dispose 不会杀已预留或已发送动作的宿主。不再添加读取移交或引用计数，避免破坏同会话浏览及任务生命周期。新增可控测试：读取在飞时执行动作仍成功，旧读取标记 Superseded；重新右键取代读取也不形成真实错误。 |
| 真实读取连接断开后恢复 | 排查发现真实问题：失败连接可能仍留在 _current，使下一次 Open 再失败一次。Expand 在有效当前连接关闭时清掉 _current，Open 也跳过 Closed 连接。可控测试宿主故意退出，检查当前失败仍是真失败，随后第一次 Open 直接恢复。此夹具只在 --shell-test-host 生效，不进入真实 Shell 宿主。 |
| 持续 Concat/Distinct 和键盘整树重建 | 采纳每次呼出独立维护命令索引。NativeMenuState 以 TryAdd 保留先到的命令身份，合并新 ID 后使行快照失效；无搜索重建及键盘命令匹配复用同一会话的行快照，搜索仍按文本过滤，树补全后重新建立快照。ShowAt 清掉所有旧动作，不跨右键请求缓存命令或状态。 |
| 一次呼出执行一个原生命令 | 保留原生菜单的常规行为：选择动作后整个菜单关闭，需要继续操作时再次右键。README 说明此行为，旧调用的提示改为“此菜单已结束，请重新右键继续操作”。不把内部 session 术语放进用户操作流程，也不改一次性新建回调 TCS。 |

新增逻辑测试覆盖快照复用、重复 ID 的先到者胜、换代后同 ID 的新委托、树更新及搜索不污染完整快照。界面检查覆盖分组取消、旧分组真失败、当前真失败和搜索取消；传输压力检查覆盖读取/执行队列、取代、真实断连和恢复。

界面测试夹具同时加固：动画等待实际呈现的终帧（上限 2 秒，仍保留首次呈现小于 250ms 的原断言）；焦点转移检查先激活根菜单，在加载完成的正常优先级提交后检查焦点意图，避免后台启动器没有前台权限时的正常失焦关闭干扰该断言。持续的前台、整链点击和关闭另用实际输入夹具检查。失败诊断保留 root/side 状态，避免空引用导致后续检查全部中断。没有删掉焦点断言或跳过门禁。

保持 WPF、独立 Shell 宿主、原生命令映射、透明内容同步和既有动画方案。没有重新测量跨版本性能百分比，也没有声称覆盖全部第三方扩展、混合 DPI 和远程桌面。最终结果及发布身份见 QA-1.2.0.md。
