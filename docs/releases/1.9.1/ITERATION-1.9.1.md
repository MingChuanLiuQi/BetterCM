# BetterCM 1.9.1 — 2026-10-23

本轮聚焦稳定性和可核对的发布证据，配置 schema 仍为 2，不增加自定义动作字段。

## 行为变化

1. 网络程序与本地程序分别限流为四个探测。UNC、扩展 UNC 和映射网络盘进入网络池，并使用独立线程，避免不可取消的网络文件系统调用占住本地名额或共享线程池。每个调用最多等待 250 ms；失败或超时的网络路径退避两秒，退避表最多 128 项。已发出的底层调用仍等待系统返回，未实现强制终止它的辅助进程。
2. 接管右键松开或接收热键消息时记录单调时钟，随后记录请求排队、上下文、Shell、动作准备、窗口 Show 后及 WPF 呈现观测的累计耗时。最近 32 次已结束请求展示于诊断页及脱敏诊断包。未确认键盘焦点、取消、过期和关闭前未呈现均不会记成成功。
3. 上下文捕获阶段也开始监听取消。新外部输入、打开设置或进入预览都会作废原捕获请求，防止旧请求迟到显示。
4. 验证回执加入逐文件源码清单与源码树 SHA256，并在开始/完成验证、复用发布载荷及打包时核对。安装器同时输出便携包、发布清单及证据。旧回执缺少源码身份时必须重新验证。
5. 新增 Build-Candidate.ps1：复制当前源码到独立 Git 快照，逐文件核对，完整验证后运行原安装器门禁。候选保留原工作区身份、快照提交、精确源码 ZIP、Git bundle、安装包和哈希；不会提交主工作区。-SkipDesktopChecks 显式产生 Internal 范围；-InstallerSmoke 追加 QA 独立安装身份检查，不能与跳过桌面验证混用。

## 回归与证据

新增 15 项 xUnit 回归、6 项 PowerShell 源码身份回归及 5 项 UI/Shell 检查。开发阶段已运行 324 项 xUnit、73 项脚本回归和 298 项 UI/Shell 自检。最终完整快照验证及安装结果应读取候选目录内的原始报告，不能从这些开发阶段数字推导。

`artifacts/iteration-1.9.1/` 保存开发阶段证据。`artifacts/candidates/1.9.1-<UTC时间>-<标识>/candidate-manifest.json` 只在快照验证及打包全部成功后生成，记录快照提交、原提交、源码树哈希及完整交付文件哈希。`package/release-manifest.json` 与 `package/evidence/` 保存快照的发布回执。若运行 -InstallerSmoke，另有 `installer-evidence/` 和日志。

输入请求的自动化检查使用合成请求进入真实 App/上下文/Shell/窗口编排；另有无动画、动画、取消和旧代次隔离检查。它不等同于物理鼠标/热键输入测试。呈现观测在 WPF Rendering 回调结束后采样焦点，不代表显示器扫描、完整动画完成或端到端性能承诺。尚未设定新的整体响应阈值。

本轮没有新增远程服务或上传遥测。未完成真实代码签名、干净 VM、远端 CI/CodeQL、混合 DPI 和读屏实测。QA 独立身份安装检查不代表最终正式身份 Setup 已安装，也不代表公开发布。
